# ADR-0051: Automatic blank-line + horizontal-rule separator before `footer`

- **Status**: Accepted
- **Date**: 2026-08-31
- **Deciders**: bchatard

---

## Context

Once `footer` (ADR-0049) rendered directly after the last section with no deliberate spacing, the
built-in credit line sat immediately under the final commit bullet with no visual break — a live
run showed `<!-- heraut-footer -->` (invisible) followed on the very next line by
`_Generated by [heraut]..._`, right under `- Init project - (...)` with nothing to separate
heraut's own signature from the release content. Reported as needing "a clean separation."

## Decision

Whenever `footer` is non-empty — built-in default or a full user override — heraut now inserts a
blank line and a Markdown horizontal rule (`---`) immediately before it:

```
...last commit line

---
_Generated by [heraut](https://github.com/adaouat/heraut) 1.2.3 at 14:30 on 2026-08-31._
```

This is **structural**, the same category as the section anchors and `footerAnchor`: applied by
the assembly layer (`appendFooter` in `internal/generators/native/changelogfile.go`, and inline in
`renderReleaseNotes`), not part of `footer`'s own template text, and therefore not something a
`footer` override can opt out of short of nulling the block entirely (`footer: ""`, which skips the
separator along with everything else — `appendFooter` is a no-op on an empty footer).

`renderPostamble` no longer owns any of the surrounding whitespace: it now returns just the
trimmed block output (empty string when unset), and every caller (`buildAllSections`,
`spliceSection` via `appendFooter`, `renderReleaseNotes`) is responsible for its own presentation
— the changelog callers via the shared `appendFooter`/`footerSeparator`, release notes inline
since it has no anchor to manage.

## Consequences

- **No public release affected** — same as ADR-0049/ADR-0050, this lands before the buggy
  `v0.60.0`-era footer output (see the roadmap note) is superseded by the next
  `heraut changelog --regenerate`.
- **A user override can't suppress just the separator.** Choosing between "default footer, no
  separator" and "custom footer, with separator" isn't expressible — the separator is tied to
  "is footer non-empty," not to which content fills it. Not requested; not built.
- **Golden files updated.** The 4 release-notes goldens gained the blank line + `---` before their
  footer line; the changelog goldens were already footer-free (ADR-0049 moved the footer out of the
  per-section render they test) and are unaffected.

## Alternatives considered

- **Bake the separator into the built-in `footer` template text instead of the assembly layer.**
  Rejected: `renderPostamble` trims the block's own output (same as `renderPreamble` does for
  `title`/`subtitle`) specifically so presentation is controlled once, consistently, regardless of
  how a user's override snippet is whitespace-formatted — leading/trailing blank lines a user types
  into their own override would otherwise be silently swallowed by that same trim, making the
  separator's presence depend on template-authoring accident rather than being guaranteed.
