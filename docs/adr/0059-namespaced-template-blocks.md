# ADR-0059: Namespaced template blocks (`release.*` / `commit.*`)

- **Status**: Accepted
- **Date**: 2026-09-14
- **Deciders**: bchatard
- **Supersedes**: the block-set table in [ADR-0049](0049-changelog-release-notes-footer-block.md)
  (`release_header`→`release.section`, `group`→`release.group`, `contributors`→
  `release.contributors`, `stats`→`release.stats`, `release_footer`→`release.footer`,
  `commit`→`commit.message`, `ticket`→`commit.ticket`, `contributor`→`commit.contributor`);
  document-level `title`/`subtitle`/`footer` and the `changelog`/`release_notes` document-root
  overrides are unchanged.

---

## Context

[ADR-0037](0037-native-template-api.md)/[ADR-0048](0048-changelog-title-subtitle-blocks.md)/
[ADR-0049](0049-changelog-release-notes-footer-block.md) grew `rendering.templates` into a flat,
13-key namespace: `title`, `subtitle`, `footer` (document-level, once per document);
`release_header`, `group`, `commit`, `ticket`, `contributor`, `contributors`, `stats`,
`release_footer` (release/sub-release cadence); and the whole-document roots `changelog` /
`release_notes`. The flat key alone doesn't say how often a block fires or what it executes
against — only `release_header`/`release_footer` carry a `release_`-prefix hint, while `group`,
`commit`, `ticket`, `contributor`, `contributors`, and `stats` fire on the same release/sub-release
cadence with no prefix at all. A user has to open the spec table before writing any override.

This surfaced while drafting a fires/renders reference table for spec 05: laying every block out
in one flat list made the inconsistency visible, and the fix is a config-surface change, not just
a doc fix — group the blocks by what already varies orthogonally (document-level vs.
per-release vs. per-commit) instead of prefixing them.

## Decision

Nest the release- and commit-cadence blocks under `release:`/`commit:` YAML objects. The
document-level trio (`title`/`subtitle`/`footer`) and the two document-root overrides
(`changelog`/`release_notes`) stay flat — they have no release/commit-scoped counterpart to
disambiguate from:

```yaml
rendering:
  templates:
    title: "# Changelog"
    subtitle: "All notable changes."
    footer: "_Generated by heraut._"
    changelog: "..."          # whole-document root override
    release_notes: "..."      # whole-document root override
    release:
      section: "## [{{ .Version }}]({{ .CompareURL }}) - {{ date \"2006-01-02\" .Date }}"
      group: "{{ .HeadingPrefix }} {{ .Name }}"
      contributors: "..."
      stats: "..."
      footer: ""
    commit:
      message: "- {{ .Description }} ({{ .ShortHash }})"
      ticket: "([{{ .Text }}]({{ .Href }}))"
      contributor: "* @{{ .Author.Username }} made their first contribution"
```

### Block set (supersedes ADR-0049's table)

| Key | Was | Context (`.`) | Fires | Renders |
|---|---|---|---|---|
| `title` | unchanged | bare `tplHeraut` | once per document | Document heading |
| `subtitle` | unchanged | bare `tplHeraut` | once per document | Sub-heading below title |
| `footer` | unchanged | bare `tplHeraut` | once per document | Document-level credit line |
| `release.section` | `release_header` | `Release` | once per rendered release | The `## [version]` section heading |
| `release.group` | `group` | `Group` | once per type group | The group heading (e.g. `### Features`) |
| `release.contributors` | `contributors` | `Release` | once per release (release-notes root only) | Whole contributors section |
| `release.stats` | `stats` | `Release` | once per release (release-notes root only) | Whole stats block |
| `release.footer` | `release_footer` | `Release` | once per rendered release | Per-release trailing block (default empty) |
| `commit.message` | `commit` | `Commit` | once per commit | One commit line |
| `commit.ticket` | `ticket` | each `.Tickets` entry | once per matched ticket | One ticket link within a commit line |
| `commit.contributor` | `contributor` | `Contributor` | once per contributor | One contributor line |
| `changelog` | unchanged | `Release` | — | Changelog document root (whole-document override) |
| `release_notes` | unchanged | `Release` | — | Release-notes document root (whole-document override) |

### Naming notes

- **`release.section`, not `release.header`.** [ADR-0038](0038-incremental-changelog.md)'s own
  vocabulary for the anchored per-release unit is "section" (`<!-- heraut-release: vX.Y.Z -->`);
  reusing "header" here would also read as the same kind of block as `title`/`subtitle`
  (whole-document headers), which it isn't.
- **`commit.message`, not bare `commit`.** Nested under `commit:`, a bare `commit` key would sit
  next to `ticket`/`contributor` reading as if it names the data type rather than the line it
  renders; `message` says what it produces.
- **Nested object, not a flat dotted-string key** (`"release.section": "..."`). A nested YAML
  object is what a user would write on first instinct, visually groups related overrides, and
  lets `schema.json` document the two sub-namespaces (and enforce `additionalProperties: false`)
  independently. Go's `text/template` block names are unaffected either way — they're just
  strings — so this is purely a config-surface/ergonomics choice, not a rendering-engine one.

## Consequences

- **Breaking rename, no alias.** Consistent with ADR-0048/ADR-0049's precedent and the project's
  pre-v1.0 stance (SemVer 0.x): every flat key under `rendering.templates` other than
  `title`/`subtitle`/`footer`/`changelog`/`release_notes` stops validating. The config
  validator's existing "unknown template block" error is the only migration signal — no
  deprecation window, no dual-key support.
- **Config struct gains a nesting level.** `internal/config`'s template-overrides struct grows two
  nested structs (`Release{Section, Group, Contributors, Stats, Footer}`,
  `Commit{Message, Ticket, Contributor}`); the existing deep-merge (global → per-driver → per-env,
  [ADR-0019](0019-perenv-content-driver-merge.md)) must merge these field-by-field one level
  deeper, not just at the top of the map.
- **`schema.json`** gains `release`/`commit` sub-objects under `rendering.templates`, each
  `additionalProperties: false`, same enforcement as today's flat object.
- **Internal template block names may stay dotted strings.** `internal/generators/native`'s
  `text/template` blocks can keep names like `{{ define "release.section" }}` — the config loader
  is what flattens the nested YAML into that dotted key when building the snippet map consumed by
  `buildTemplateSet`; `blocks.tmpl`/`changelog.tmpl`/`release_notes.tmpl` only need their
  `{{ template "..." }}` call sites and `{{ define }}` names updated to match.
- **Every doc surface naming the old keys needs updating**: `docs/specs/05-generators-and-platforms.md`
  (the "Overridable blocks" list and data-model prose), `schema.json`, `docs/heraut.sample.yml`,
  and `docs/guides/template-customization.md` if it enumerates individual keys. Left for the
  implementation task, so specs continue to describe shipped behavior until the rename lands.

## Alternatives considered

- **Flat dotted-string keys** (`"release.section": "..."` as a literal map key, no YAML nesting).
  Rejected: zero config-struct change, but doesn't read as a group in the YAML file and can't let
  `schema.json` describe the two sub-namespaces independently — the whole point of this rework is
  legibility, which a flat key with a dot in it doesn't buy.
- **Keep flat names, just fix the prefix inconsistency** (e.g. `group`→`release_group`,
  `commit`→`commit_message`, prefixed but not nested). Rejected: same information, worse ergonomics
  — a flat 13-key list is no easier to scan than today's, and doesn't stop the list from growing
  flatter as more blocks are added.
- **A backward-compatible alias for the old keys.** Rejected: no other block rename in this
  codebase has one ([ADR-0048](0048-changelog-title-subtitle-blocks.md),
  [ADR-0049](0049-changelog-release-notes-footer-block.md)); pre-v1.0 breaking changes are the
  established norm here.
